# 知识库与自进化

## 1. 定义

- RAG 负责检索已有资料。
- 知识库负责保存、分类、权限、版本和引用。
- 自进化负责从修改和结果中生成可验证的方法变化。
- 模型微调不进入 P0。

系统不宣称自主变聪明。它提供的是用户可控、可追溯、可撤销的项目学习闭环。

## 2. 四层知识

1. 项目资料：Brief、方案、排期、会议、报价、周报和物料。
2. 客户/品牌知识：品牌规范、客户偏好、审批规则和历史活动。
3. 个人/团队 Playbook：标准流程、工期、检查项、成功方法和失败反例。
4. 结果与评估：实际工期、修改、KPI、延期和知识使用效果。

原始项目资料默认只属于当前项目。只有用户确认后的抽象结论才能提升到客户或工作空间范围。

## 3. 摄取流程

```text
上传原件
-> 杀毒/类型检查
-> 保存不可变版本
-> 文档解析/OCR
-> 结构识别和分块
-> 元数据与权限标记
-> 全文和向量索引
-> 用户检查提取结果
```

每个分块保留文件版本、页码或位置、解析器版本和内容哈希。解析失败不能阻止原件保存。

## 4. 检索流程

1. 按组织、工作空间、客户、项目和权限过滤。
2. 按项目类型、阶段、地区、日期和知识状态过滤。
3. 组合关键词和语义检索。
4. 根据来源质量、时效、结果证据和作用域重排。
5. 返回引用位置、适用范围和不确定性。
6. 记录用户采用、忽略、纠正或举报结果。

向量相似度不能绕过权限，也不能把历史方案的假设包装成当前事实。

## 5. 项目结束后的知识包

项目完成时生成 Project Capsule：

- 原始 Brief 和最终确认方案。
- 市场证据、关键假设和最终决策。
- 计划排期与实际排期。
- 变更、延期、风险和处理方式。
- 计划指标、实际结果和数据来源。
- 用户明确记录的复盘。
- 可复用资产和候选经验。

Project Capsule 是项目归档视图，不会自动成为团队知识。

## 6. 学习闭环

```text
AI 初稿
-> 用户接受/修改/驳回并记录原因
-> 实际执行和结果
-> AI 对比计划、终稿与结果
-> 生成候选知识
-> 用户选择作用域和状态
-> 下个项目显式引用
-> 评估是否改善
-> 保留、修订或停用
```

### 候选知识类型

- 品牌和客户规则。
- 任务模板与前后依赖。
- 历史工期与缓冲建议。
- 风险检查项。
- 成功案例模式。
- 失败反例。
- KPI 和数据采集规则。

### 状态

`candidate -> approved -> active -> needs_review -> retired`

每条知识保存来源、适用范围、确认人、证据数量、最后验证时间、采用次数和撤销记录。

## 7. 自动化边界

P0：自动捕获反馈，自动生成候选知识，人工确认后生效。

后续只有低风险、重复出现且通过评估的规则才可以默认应用；用户仍能看到引用并撤销。以下内容永不自动提升：客户机密、合同和价格、个人信息、未经核实的市场判断、法律结论和单次创意偏好。

## 8. 如何判断系统真的变好

- 后续项目首稿保留率提高。
- 相同错误复发率下降。
- 排期预测与实际工期误差下降。
- 历史知识被采用后减少修改或风险。
- 候选知识的批准率、撤销率和过期率可见。
- 没有跨客户检索和错误引用。

不能只用知识条目数量、向量数量或聊天满意度衡量自进化。
