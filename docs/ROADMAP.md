# 路线图

路线图按风险和依赖排序，不按功能数量排序。每个里程碑只有通过对应验收后才进入下一阶段。

## M0：规格、样本与技术验证

- 冻结产品边界、数据分类和权限规则。
- 准备至少两个来源可核对的 AI 时代公开案例重构和一个可执行合成测试项目；真实资料作为可选增强，不阻塞 M0。
- 验证文档解析、结构化输出、排期计算和混合检索。
- 确定 PostgreSQL/pgvector、对象存储接口和任务队列实现。
- 完成第三方许可证审计。

退出条件：公开重构与合成样本通过结构检查，数据模型得到确认，关键依赖无许可证阻塞。该条件只允许进入工程验证，不代表真实需求成立。

## M1：项目与排期纵向闭环

- 项目、客户、文件版本和方案导入。
- 交付物、任务、依赖和倒排计划。
- 甘特图、状态、阻塞和实际工期。
- CSV/XLSX 导出。
- 基础审计日志和错误恢复。

退出条件：一个真实脱敏项目能够从确认方案走到可执行排期，关键依赖无严重遗漏。

## M2：知识库与项目学习

- 文档解析、全文与向量检索。
- 项目、客户和工作空间隔离。
- 引用、反馈和版本追踪。
- Project Capsule、候选知识审批和新项目复用。

退出条件：用项目 A 的批准知识改善项目 B，且没有跨客户泄漏。

## M3：市场信号与影响分析

- 用户指定网页、RSS 和人工信号导入。
- 信号去重、来源、时间和可信度。
- 信号到假设、交付物和任务的影响关系。
- 人工批准的变更流程。

退出条件：监测结果能在真实项目中产生可解释的行动，且噪音可控。

## M4：报告、飞书与团队能力

- 周报、风险报告和复盘导出。
- 飞书官方 API 连接器。
- 多用户、角色、审批和项目组合视图。
- 私有部署运维、备份和恢复。

退出条件：小团队可以在不依赖开发者持续手工维护的情况下完成一个项目周期。

## M5：商业验证与扩展

- 至少一个真实项目的重复使用和付款/订金测试。
- 评估托管云、企业私有部署和实施服务。
- 再决定企微、GEO、媒体监测、PPTX 和更多项目模板。

## 实现顺序

1. 数据与权限契约。
2. 方案到排期的单条闭环。
3. 人工评审和失败恢复。
4. 文件、引用、版本和导出。
5. 知识学习与评估。
6. 市场监测和连接器。
7. 团队权限和视觉完善。
