# M0-04 混合检索与引用验证报告

状态：`Validated technical spike`

## 结论

M0-04 已验证一个无第三方运行时依赖的确定性检索原型：它在评分前执行工作空间、客户、项目和可见性过滤，组合 BM25 风格词法分数与字符 n-gram 语义代理分数，并为结果返回可校验的来源路径、版本 SHA-256、位置和摘录。

本结论只适用于仓库中的合成语料与冻结查询。它不证明真实中文营销资料的召回质量、模型答案正确性、用户效率提升、复用意愿或付费价值。

## 已确认行为

- 16 个黄金查询通过，其中 13 个英文场景、3 个中文场景。
- 同项目、同客户跨项目和显式工作空间已批准知识按冻结范围返回。
- 跨客户近似内容和跨工作空间稀有诱饵没有进入授权结果。
- 范围过滤先于评分；拒绝的 chunk 不进入评分候选计数。
- 缺失工作空间、缺失项目所需客户、未知工作空间、客户不匹配和未知项目均 fail-closed。
- 相同输入重复运行时，排序、引用和运行 hash 一致。
- 来源文件被篡改后，旧引用返回 `source_hash_mismatch`。
- 非字符串或空 `sourcePath` 返回结构化 `invalid_citation`，不会抛出未处理的路径类型异常。
- CLI 可以直接读取冻结的黄金查询文件，并报告引用校验结果。

可复现证据：

- `scripts/hybrid_retrieval_spike.py`
- `scripts/check_hybrid_retrieval.py`
- `validation/fixtures/retrieval-spike-001/`
- `validation/results/m0-04-hybrid-retrieval.json`

## 实现边界

处理顺序固定为：

```text
查询校验 -> 范围硬过滤 -> 词法评分 -> 字符 n-gram 代理评分
-> 混合稳定排序 -> 带版本引用结果 -> 引用新鲜度校验
```

中文词法处理将连续 CJK 文本确定性展开为单字与相邻双字 token，使短语局部匹配不依赖外部分词服务。该方法有利于可重复测试，但不是语言学分词，也不是生产 embedding。

默认最低词法覆盖率为 `0.6`。中文场景是在保留该门槛的情况下通过，未通过降低或关闭阈值绕过召回问题。

## 无法由本验证确认

- 合成短文本不能代表真实方案、合同、复盘、表格和长文档的分布。
- 16 个查询不能给出召回率、准确率、误报率或中文语义质量的统计结论。
- 字符 n-gram 对同义词、行业缩写、错别字、长距离语义和跨语言查询的表现尚未验证。
- 本原型没有验证向量索引的规模、更新、删除、备份、迁移和多进程并发。
- 技术隔离通过不等于权限系统已经生产可用；应用层身份、数据库行级权限和审计仍需后续实现。
- 网络案例与合成 fixture 不能证明市场需求、ROI、时间节省、重复使用或付费意愿。

## M0-05 决策输入

M0-05 需要比较并记录生产候选的版本、许可证、维护信号、私有部署方式和替代方案，至少覆盖：

1. 中文及跨语言分词或 embedding 模型。
2. 词法索引、向量索引与混合排序组件。
3. workspace/client/project 过滤是否能在查询执行层先于向量评分。
4. 来源版本、删除传播、重建和引用新鲜度机制。
5. CPU、内存、模型下载、离线部署和 BYOK 边界。
6. 依赖失效时保留当前确定性词法回退的可行性。

在 M0-05 完成前，不应把本脚本直接接入真实客户资料或宣称为生产 RAG。
