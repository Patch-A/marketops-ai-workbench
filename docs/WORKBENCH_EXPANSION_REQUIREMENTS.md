# 工作台扩展需求与落地顺序

状态：`information architecture confirmed, shell implemented, feature slices pending`。六个一级业务页面、设置中心、生图入口和 Obsidian 知识库连接方向已经由用户确认；工作台壳和总控台入口已落地，本文不改变当前 M1/M2 登记状态。

## 1. 四象限结论

### 共同已知

- 当前版本已经跑通“已批准方案 -> 候选审核 -> WBS/排期 -> 执行状态 -> CSV/XLSX 导出”。
- 当前版本的真实定位是 M1 执行切片，不是完整营销工作台。
- 目标工作台需要覆盖活动项目、产品营销、市场研究、内容/GEO、监测、素材生产和日程管理。
- 用户当前要的是先交付可操作产品，再通过本人和朋友的多轮试用收集问题；ROI、复购和付费不应成为本阶段开发门槛。
- 外部平台、模型服务、搜索引擎和图片生成服务都存在授权、配额、稳定性和数据发送边界。

### 你的已知 / 我的未知

首个主场景是活动运营还是产品/GEO 运营、第一批模型是否只接 OpenAI-compatible/DeepSeek、首批监测渠道是否采用官方 API/RSS/人工录入，目前还没有完全确定。默认假设是先做单操作者、私有部署、可插拔连接器，并以一个产品、一个市场和一组固定查询完成闭环。

### 你的未知 / 我的已知

- “分析各大搜索引擎的搜索习惯”不能承诺全网真实排序。可交付的是带来源、时间和查询条件的搜索结果样本、关键词机会分析和可执行建议。
- “在各大 AI 平台用关键词提问并监控结果”需要逐个平台授权或官方接口；不能把未授权的批量爬取或绕过限制当成产品能力。
- 模型匹配不是一个下拉框。它至少需要能力标签、隐私范围、上下文长度、成本、延迟、可用性、视觉/生图/嵌入能力和故障回退策略。
- 生图功能需要保存提示词、模型版本、输入素材授权、生成时间、资产版本和人工审核结果，否则后续无法复用或追踪。
- SEO、GEO、内容分发、项目执行和日历的事实来源不同，必须分域存储并通过项目关系连接，不能全部塞入助手聊天记录。

### 共同未知

本阶段需要用小规模真实试用确定哪个工作流带来最高频、最明确的下一步行动。暂不把覆盖平台数量或生成数量当成成功指标，优先记录用户是否保留结果、是否继续编辑、是否再次打开同一工作区，以及失败原因。

## 2. 产品工作定义

### Job statement

对于负责活动、品牌或产品营销的项目负责人，在收到 Brief、产品变化或市场问题时，帮助其完成研究、方案、内容、排期、监测和反馈的可追溯协作，从而减少资料切换和重复汇总，并明确下一步由谁在什么时候执行。

### 用户与入口

| 用户 | 入口 | 主要输出 |
|---|---|---|
| 活动/项目负责人 | Brief、活动方案、会议纪要、日期约束 | 研究摘要、方案草案、WBS、风险、周报 |
| 产品/内容负责人 | 产品资料、目标市场、内容目标 | 关键词地图、内容计划、渠道分发包 |
| GEO/SEO 运营人员 | 固定查询集、竞争页面、AI 平台问题集 | 可见性快照、缺口诊断、优化任务 |
| 设计或增长协作者 | 已批准内容、品牌规范、参考素材 | 生图资产、版本、审核记录 |

第一版仍以单操作者为主，团队角色、客户审批和组合视图后置。

## 3. 目标工作流

```text
Capture -> Clarify -> Research -> Draft -> Review -> Approve
-> Plan -> Execute -> Monitor -> Change -> Report
-> Create assets -> Distribute -> Retrospect -> Learn
```

每一步都保留四类对象：

1. `fact`：有来源、时间和范围的事实。
2. `hypothesis`：模型或人工提出、尚未证实的判断。
3. `decision`：人工接受、修改或拒绝的决定。
4. `outcome`：执行后记录的实际结果，不能由模型自动补齐。

## 4. 功能地图

### A. 模型中心与任务匹配

模型注册需要记录供应商、兼容协议、endpoint、模型名、版本、启用状态、能力标签、上下文长度、结构化输出、工具调用、区域和数据保留声明。还需记录成本区间、延迟观测、额度、健康状态和最近失败原因。密钥只保留在服务端环境或部署方密钥存储，浏览器只看到脱敏名称。

任务匹配需要为研究、提纲、长文、关键词聚类、分类、审核、生图、嵌入等任务定义类型。每种任务配置首选模型、备用模型、超时、预算上限和人工接管条件。运行前显示将发送的数据范围；运行后保存模型、版本、输入哈希、耗时、成本和输出状态。用户可以手动指定模型，也可以使用可解释的匹配建议。

### B. Brief、产品和市场研究

- 导入 Brief、产品资料、竞品页面、会议纪要和批准方案。
- 选择产品、产品类型、目标市场、受众、业务目标和周期。
- 系统提出缺失问题，用户确认后创建研究任务。
- 研究任务支持官方网页、RSS、用户提供 URL、上传资料和人工摘录；每条结论带来源、时间、置信度和适用范围。
- 输出市场概览、受众问题、竞品对照、主题机会、风险和待确认问题。
- 研究结果进入草案，不能直接变成正式方案或外部文案。

### C. 方案生成与审批

- 根据 Brief 和研究结果生成结构化方案草案：目标、受众、主张、渠道、内容、活动、依赖、风险、指标和未知项。
- 支持版本比较、逐段引用、人工接受/修改/拒绝和审批原因。
- 审批后才能进入当前已实现的 WBS/排期链路。
- 模型不能直接改正式方案、日期、预算或对外消息。

### D. 关键词与搜索可见性

关键词工作台需要支持种子词、同义词、问题词、品牌词、竞品词、行业词和地域词，并记录目标市场、语言、设备、搜索引擎、抓取时间和来源。输出包括关键词聚类、意图分类、主题覆盖、内容缺口和优先级建议。

优化诊断需要回答页面或内容是否覆盖目标问题、标题和摘要是否清晰、证据是否充分、内外部链接是否合理。系统必须区分“未观测到”和“确认不存在”，不能把一次搜索结果当成稳定排名。建议要落到具体任务，例如补充哪段内容、增加哪类证据、更新哪个标题或建立哪条内部链接。

首批搜索引擎和 AI 平台只支持用户明确选择的来源和固定查询集。每次快照保存平台、查询、时间、地区/语言、结果引用和抓取状态。AI 平台结果标记为观测样本，不宣称覆盖全部用户答案或真实市场份额。

### E. 内容运营与分发

- 内容 brief、文章、短帖、问答、邮件等类型模板。
- 渠道适配：标题长度、格式、链接、图片尺寸、免责声明和发布时间。
- 生成分发包，先人工审核，再通过官方 API 或导出文件发布。
- 记录发布状态、版本、渠道、发布时间、失败原因和撤回入口。
- 第一版不做全功能 CMS、CRM 或个人账号自动化。

### F. 图片生图与素材库

- 生图任务包括用途、尺寸、风格、品牌约束、参考素材和负面约束。
- 选择具备生图能力的模型，保存模型版本和提示词。
- 生成结果进入资产库，支持标记、裁切、版本、人工审核和下载。
- 记录输入素材授权和平台条款状态；未经确认的肖像、商标和客户素材不得发送。

### G. 日程与项目指挥台

- 今日、未来 7 天、未来 30 天视图。
- 重点工作、负责人、截止日、依赖、提醒、阻塞和来源项目。
- 从批准 WBS、研究任务、内容分发包和监测告警生成待办，但仍需人工确认。
- 支持 ICS/CSV 导出；日历连接器后置到官方 API 和权限审查完成后。

## 5. 第一阶段建议范围

为了让产品尽快从执行切片变成可用工作台，建议下一阶段只做以下一条新纵向链路：

```text
Brief/产品 -> 研究任务 -> 关键词与主题机会 -> 方案草案
-> 人工批准 -> 现有 WBS/排期 -> 未来 7/30 天重点工作
```

第一阶段交付：

1. 模型中心：注册 2-3 个兼容模型，完成任务能力匹配和服务端密钥边界。
2. Brief/产品入口：产品类型、目标市场、受众、目标和周期。
3. 研究任务：固定来源、用户输入 URL/RSS 和结构化研究结果。
4. 关键词工作台：种子词、意图、聚类、内容缺口和可执行优化任务。
5. 方案草案：引用、事实/假设区分、版本审核和批准。
6. 7/30 天日程：从批准计划和研究任务生成重点工作。

第一阶段暂不做：全网排名承诺、全平台自动发文、批量 AI 平台爬取、自动外发、自动预算/ROI、团队权限、个人微信和复杂图像编辑器。

## 6. 数据与状态契约

核心实体包括 `Workspace`、`Client`、`Project`、`Brief`、`Product`、`Market`、`ResearchRun`、`Source`、`Query`、`Keyword`、`ContentAsset`、`Channel`、`ModelProfile`、`Task`、`Signal`、`CalendarItem`、`Approval` 和 `AuditEvent`。

长任务统一使用 `queued -> running -> partial | needs_review | succeeded | failed | cancelled`。部分成功必须展示已完成项、失败项、重试和人工继续入口。模型不可用、连接器超时或平台限流不能覆盖已保存的项目事实。

权限和隐私边界：

- 客户、工作区和项目作用域先于检索和模型评分。
- 原始文件、派生文本、提示词、生成资产和外部响应分开存储。
- 模型调用前显示数据发送范围；默认不把客户文件用于训练或跨项目记忆。
- 所有外发、发布、知识提升、正式方案变更和连接器授权写入审计。

## 7. 实施顺序与验收

### W0：模型中心基础

验收：可添加、编辑、停用模型；密钥不出现在浏览器、日志或导出；同一任务可看到匹配理由和备用模型；失败能人工重试或切换。

### W1：Brief/研究/方案草案

验收：一个去标识产品 Brief 能完成缺失问题确认、研究运行、引用结果、方案草案和人工批准；没有来源的内容标为假设或未知。

### W2：关键词/GEO 监测最小闭环

验收：固定 20 个查询、2 个搜索来源和 1 个 AI 平台样本可以重复抓取，结果带时间和引用；系统生成的每条建议都能指向关键词、内容缺口或下一步任务。

### W3：生图与日程

验收：一个已批准内容 brief 能生成带模型版本和授权记录的资产，并进入 7/30 天日程；失败、撤回和人工审核路径可用。

### W4：朋友私有试用

验收：Docker 私有部署、TLS、独立账号、备份/恢复、数据隔离和部署说明完成；朋友能在不依赖开发者手工改数据库的情况下完成一个项目周期。

## 8. 最小验证实验

这些实验是产品可用性实验，不是 ROI 或市场 Go/No-Go：

| 实验 | 单一变量 | 成功信号 | 需要回收 |
|---|---|---|---|
| 模型匹配 | 同一研究任务切换首选模型 | 用户能理解并接受匹配/切换，不出现凭据泄露 | 模型、耗时、失败、人工切换原因 |
| Brief 到方案 | 是否增加研究和缺失问题步骤 | 用户保留或小改后保留大部分结构，能指出遗漏 | 修改位置、删除原因、继续动作 |
| 可见性快照 | 固定查询集的重复运行 | 快照可复现，建议能转成具体内容任务 | 查询、时间、来源、结果差异 |
| 生图 | 一个内容 brief 生成一组资产 | 用户能选出可继续编辑或使用的版本 | 提示词修改、拒绝原因、授权状态 |
| 日程 | WBS/研究任务进入 7/30 天视图 | 用户实际用它安排下一周工作 | 新增、移动、取消和阻塞原因 |

## 9. 已确认的产品信息架构

### 9.1 产品核心

产品核心不是单独的活动执行或 GEO 工具，而是一个营销工作总控台：

```text
Brief / 资讯 / GEO 观测 / 模型输出
-> 可审核的判断与下一步
-> 项目 / 内容 / GEO 任务
-> 日程
-> 执行结果与反馈
```

首页负责回答四个问题：

1. 哪些重点项目正在推进，当前阶段、进度、阻塞和下一步是什么？
2. GEO 项目最近一次观测发生了什么变化，哪些变化需要行动？
3. 今天、本周和本月有哪些必须处理的任务？
4. 今天有哪些与当前产品、市场和项目有关的重点资讯，为什么值得关注？

### 9.2 主导航

第一版采用六个一级业务页面。生图保留完整工作页，但归属“内容与资产”；模型与连接归入设置中心，不占一级业务导航。

| 顺序 | 导航 | 职责 |
|---|---|---|
| 1 | 总控台 | 项目进度、GEO 快照、今日待办、重点资讯和快捷操作 |
| 2 | 项目 | 活动、品牌和产品营销项目；Brief、研究、方案、排期、执行和复盘 |
| 3 | 研究与情报 | 重点资讯、市场/竞品研究、研究任务、研究报告和来源管理 |
| 4 | GEO | 产品/市场、关键词与问题集、搜索/AI 平台快照、变化和优化任务 |
| 5 | 内容与资产 | 内容任务、草案、渠道版本、图片、生图工作页、模板和 Obsidian 知识接口 |
| 6 | 日程 | 今日、本周、本月和全部任务；来源项目、截止日、阻塞和提醒 |

“日程”作为导航名称即可，页面内部再提供今日、本周、本月等视图。

设置中心管理文本/视觉/生图模型、任务匹配、数据来源、Obsidian、存储和外部工具连接。总控台和内容页面可提供“开始生图”“添加模型”等快捷入口，但不因此增加一级导航。

项目详情使用“概览、Brief、调研、方案、计划、执行、复盘”标签页。GEO、研究、内容和日程对象都必须保留来源项目关系，避免形成相互独立的工具集合。

### 9.3 总控台首屏

首屏使用安静、信息密集的操作布局，不做营销式大屏。建议包含：

- 重点项目：名称、类型、阶段、进度、风险、下一动作和负责人。
- GEO 动态：最新观测时间、查询集状态、重要变化、内容缺口和待确认建议。
- 今日待办：逾期、今日、等待他人、本周重点；支持完成、延期和进入来源任务。
- 重点资讯：来源、发布时间、与哪个项目/产品相关、可信度、为什么重要和建议动作。
- 快捷操作：新建项目、运行研究、启动 GEO 快照、新建内容、生图、添加日程。

首页数据只做聚合和行动入口。任何项目、GEO、资讯或内容的正式状态仍由对应工作区维护。

### 9.4 重点资讯

资讯模块由用户选择的来源、RSS、官方页面、人工录入或已审连接器供给。每条资讯至少保存来源、发布时间、采集时间、相关项目/产品、摘要、可信度和处理状态。

资讯状态：`new -> reviewed -> action_created | saved | dismissed`。资讯可以生成候选任务或影响关系，但不能自动修改正式方案和排期。

### 9.5 内容与资产接口

内容与资产既是生产资料库，也是其他本地工具的连接层。第一版首个知识库连接对象确定为本机 Obsidian 主库：`C:/Users/Patch/OneDrive/文档/Obsidian Vault`。连接器以只读同步优先，不把整个 Vault 自动发送给模型：

- 内容、图片、模板、提示词和发布版本使用统一资产 ID 与版本。
- 用户选择允许连接的 Obsidian 目录或笔记，未选择内容保持不可见。
- 保存 Vault、相对路径、内容哈希、修改时间、同步时间、连接状态和撤回状态；移动或删除时不得静默保留陈旧内容。
- 模型调用前按工作区、客户、项目和用户选择过滤，只发送当前任务所需片段，并显示引用来源。
- 工作台生成的候选知识默认进入待审核状态；写回 Obsidian、跨项目复用或提升为长期知识必须经人工确认和审计。
- 后续本地文件夹、S3-compatible 或其他工具继续通过相同适配器契约接入。
- 项目资料、可复用知识和生成资产保持不同作用域，不能因进入资产库自动跨项目复用。

### 9.6 对话式生图

生图页面使用任务与版本结构，而不是无状态聊天：

1. 新建生图任务：输入关键词/描述、用途、尺寸、风格、品牌约束、参考素材和模型。
2. 模型返回一组图片版本，自动进入当前任务的版本画廊。
3. 用户选中某张图片后，可继续输入修改要求；系统把选中版本作为父版本，并记录修改提示词。
4. 若要探索新的方向，创建“新任务”或“深度任务”，从当前版本分支但不覆盖原任务。
5. 每个版本保存父版本、模型、提示词、参考素材、生成参数、时间、状态和人工审核结果。

只有模型明确支持 image-to-image、局部编辑或参考图时，页面才显示对应修改能力；否则创建新的文本生图分支，不能伪装成精准编辑。

2. GEO 首批平台和地区：需要明确首批搜索引擎、AI 平台、语言和地区，避免把“国内外全部平台”写成不可兑现的能力。
3. 首个文本模型和首个生图模型的实际 API 契约、密钥部署方式以及是否支持图片编辑，需要在模型中心实施前确定。
