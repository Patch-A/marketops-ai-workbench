# 产品规格

状态：`Approved for planning`

工作名称：MarketOps AI Workbench

许可证：Apache-2.0

仓库：公开 GitHub 仓库

## 1. 已确认事实、判断与未知

### 已确认决策

- 产品是独立开源 Web 工作台，不依赖飞书、OpenClaw 或特定模型。
- 首批主攻活动/品牌代理公司，B2B 企业市场团队作为对照组。
- 第一版单人优先，但数据模型和权限边界为团队使用预留。
- 首个项目模板聚焦 B2B、品牌活动、展会和客户活动。
- 支持 Docker 私有部署和 BYOK。
- 飞书是首个可选连接器，企微随后；个人微信暂不进入范围。
- 项目资料、知识库和可控的学习闭环属于核心能力。

### 合理判断

- 单纯生成营销方案很容易被通用模型或 Agent + Skill 替代。
- 更值得验证的差异点是把已确认方案转成项目状态，并把外部变化映射到受影响的假设、交付物和任务。
- 企业可能为减少同步、返工、漏项和知识流失付费，但尚未通过真实付费行为确认。

### 尚未确认

- 最强付费价值来自排期、执行监控、市场预警还是复盘知识。
- 首批客户更愿意购买托管服务、私有部署还是实施服务。
- 用户愿意给系统访问哪些项目文件和外部数据源。
- 市场预警的有效频率是否足以支撑日常使用。

## 2. Job Statement

对于独立负责活动、品牌或 B2B 营销项目的市场人员，在方案被确认并进入执行时，帮助其把交付物转成有依赖、有责任人、可监控的项目计划，并在进度或外部依据变化时快速定位影响，从而减少重复同步、漏项和返工。

## 3. 用户与付费角色

| 角色 | 主要任务 | 首版权限 |
|---|---|---|
| 项目负责人 | 建项目、定计划、处理风险、输出周报和复盘 | 完整项目权限 |
| 策划/执行人员 | 更新任务、上传交付物、提供反馈 | 后续团队版本 |
| 部门或代理公司负责人 | 查看项目组合、风险、资源和方法沉淀 | 后续团队版本 |
| 客户/审批人 | 审阅指定交付物和变更 | 后续外部协作 |

## 4. 产品价值

用户不是为“多一个 AI”付费，而是为以下结果付费：

- 方案确认后不用重新手工拆排期和复制交付物。
- 修改日期、方案或依赖后，相关节点能够重新计算并提示影响。
- 项目状态、证据、决策、交付物和风险不再散落在文档、表格和群聊。
- 周报、风险报告和复盘基于真实项目状态生成。
- 历史项目的实际工期、错误和经验能够被下一项目检索和验证。
- 团队不需要自行维护一套 Agent、提示词、表格和自动化组合。

## 5. 完整用户流程

```text
Capture -> Clarify -> Research -> Proposal -> Approve
-> Plan -> Execute -> Monitor -> Change -> Report
-> Deliver -> Retrospect -> Learn -> Reuse
```

| 阶段 | 输入 | 系统行为 | 人工控制 |
|---|---|---|---|
| Capture | Brief、会议纪要、方案、资料 | 保存原件、解析、标记来源 | 确认资料范围 |
| Research | 项目资料和公开来源 | 区分事实与假设、保留引用 | 确认关键判断 |
| Approve | 最终方案和交付物 | 锁定版本、提取交付物 | 人工批准 |
| Plan | 活动日期、工期、审批和依赖 | 生成 WBS、倒排计划和关键路径 | 修改并确认计划 |
| Execute | 状态、文件、沟通和变更 | 汇总进度、识别阻塞 | 更新真实状态 |
| Monitor | 指定市场来源和假设 | 检测变化、分析影响范围 | 决定是否调整 |
| Report | 项目状态 | 生成周报和风险清单 | 审核后外发 |
| Learn | 最终结果和复盘 | 提炼候选规则和模板 | 确认、限定或拒绝 |

## 6. P0 范围

P0 必须完成一个纵向闭环：

1. 新建项目并导入一份已确认方案。
2. 保存原始文件和解析后的可引用内容。
3. 提取交付物、里程碑、约束和关键假设。
4. 生成可编辑的 WBS、依赖和倒排计划。
5. 手动更新任务状态、阻塞和实际完成时间。
6. 导入一条市场变化，显示受影响的假设、交付物和任务。
7. 生成可编辑周报。
8. 完成项目复盘并生成候选知识。
9. 用户确认后写入客户知识或个人 Playbook。
10. 新项目检索并引用已确认知识。

### P0 输出

- 项目概览和风险列表。
- 可编辑排期和甘特图。
- CSV/XLSX 排期导出。
- Markdown/HTML 周报和复盘。
- 带来源的知识检索结果。
- 项目归档包和知识提升记录。

## 7. 明确非目标

- 不做通用聊天助手或陪伴 Agent。
- 不从零重做完整 SEO、媒体分发、CRM 或舆情平台。
- 不保证全网监控、市场预测或项目结果。
- 不用模型生成的数字冒充预算、归因或 ROI。
- 不自动把所有项目资料提升为跨项目知识。
- 不自动向客户发消息、改正式方案或执行投放。
- P0 不支持个人微信非官方接入。

## 8. 状态和失败处理

每个长任务必须存在：`queued`、`running`、`partial`、`needs_review`、`succeeded`、`failed`、`cancelled`。

文件解析失败、模型不可用、监测源超时和连接器失效不能造成项目状态丢失。用户必须能看到失败原因、已完成部分、重试和人工继续入口。

## 9. 成功指标

产品指标：

- 从确认方案到首版可编辑排期的人工时间。
- 被用户保留或小改后保留的任务比例。
- 延期和阻塞被发现到处理的时间。
- 每周人工汇总项目状态的时间。
- 知识检索结果的采用率和撤销率。
- 同类错误在后续项目中的复发率。

商业验证仍以真实复用、付款或订金为强信号，不以页面访问、点赞或口头好评替代。
