# M0-04 混合检索与引用验证契约

状态：`Frozen for spike implementation`

## 验证目标

证明一个确定性技术原型能够先执行工作空间、客户和项目范围过滤，再组合词法与语义代理分数，并为每条结果返回可回到来源版本和位置的引用。任何跨工作空间或跨客户原始资料进入候选结果都视为失败。

本验证不证明生产级语义质量、真实营销知识有用性、模型回答正确性或用户付费价值。

## 输入

- 公开仓库内的合成文本块；禁止真实客户资料。
- 每块必须包含 `workspaceId`、`clientId`、`projectId`、`visibility`、来源路径、来源版本 hash 和位置。
- `visibility` 只允许 `project`、`client` 和 `workspace_approved`。
- 查询必须包含 `workspaceId`。项目资料查询还必须包含 `clientId`；项目级范围必须同时包含 `projectId`。
- 只有显式设置 `includeWorkspaceApproved` 时，才允许返回同工作空间中已批准的通用知识。

## 处理顺序

```text
查询校验
-> workspace 硬过滤
-> client/project/visibility 硬过滤
-> 词法评分
-> 确定性语义代理评分
-> 混合排序与稳定并列规则
-> 带引用结果
```

范围过滤必须先于评分。被拒绝的块不得进入分数计算、缓存、结果或任何后续模型上下文。

## 输出

每条结果至少包含：`chunkId`、范围字段、`sourcePath`、`sourceVersionSha256`、位置、原文摘录、词法分数、语义代理分数、混合分数和稳定排序序号。整个运行绑定语料与查询配置 hash。

## 强制场景

1. 同项目查询返回正确引用。
2. 同客户跨项目查询只返回该客户允许范围。
3. 显式工作空间知识查询可返回 `workspace_approved`，但不能返回其他客户原始项目块。
4. 两个工作空间放入相同稀有诱饵词，查询只能命中授权工作空间。
5. 两个客户放入相同或近似内容，查询不能越过客户边界。
6. 缺失或未知工作空间、客户不匹配、项目不匹配返回可观察错误或空结果，不得 fail-open。
7. 相同输入重复运行时，顺序、引用和 hash 一致。
8. 引用的来源 hash 与当前 fixture 文件一致；篡改来源后旧结果必须判为过期。
9. 中文查询至少覆盖同项目命中、跨客户近似内容隔离和跨工作空间稀有诱饵隔离；不能用关闭最低词法覆盖率代替中文处理。
10. 引用路径缺失、为空或类型错误时必须返回结构化失败，不能抛出未处理异常或继续读取来源。

## 评分边界

本验证允许使用标准库实现词法得分和确定性字符 n-gram/哈希向量作为语义代理，目的是验证混合检索接口、隔离顺序和引用契约。它不能被称为生产 embedding，也不能支持真实语义召回质量结论。生产依赖留给 M0-05 决策。

## 完成门槛

- 代表性查询和隔离矩阵全部通过；
- 每条非空结果都有有效引用；
- 无跨工作空间、跨客户原始资料结果；
- 错误和空结果不会扩大范围；
- 结果新鲜度检查、独立 QA 和全仓 CI 通过；
- 技术报告明确事实、推测、限制和 M0-05 决策边界。
