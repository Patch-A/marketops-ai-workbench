# AI 市场工作台市场验证执行包

> 审阅版 v0.1 | 供个人或小型市场团队直接执行 | 2026-08-08

> 定位更新说明：本执行包主要验证 Brief、证据和方案初稿。当前产品已扩展到方案确认后的排期、执行、外部变化和知识学习；这些新增假设需要按 [ACCEPTANCE_CRITERIA.md](ACCEPTANCE_CRITERIA.md) 和 [ROADMAP.md](ROADMAP.md) 增补真实项目验证，不能沿用本报告结论直接判定通过。

## 1. 验证目标

用最少样本回答三个决定生死的问题：

1. 真实 brief 进入工作台后，是否显著减少人工整理和第一版方案时间，同时不降低质量。
2. 来源、假设标记和逐段审阅是否真的减少修改与错误，而不是增加操作负担。
3. 用户是否愿意再次使用，并为下一次真实任务付费或付订金。

访谈中的“觉得不错”“以后可能会用”不计入通过。重复提交真实任务、允许继续使用资料、主动推荐同事和实际付费才是强信号。

## 2. 验证顺序

| 阶段 | 样本 | 目标 | 交付 |
|---|---:|---|---|
| 0. 二手证据 | 已完成 | 判断是否值得测试、识别边界 | 证据地图 |
| 1. 轻量问题访谈 | 5 人 | 找出现有流程、返工原因、资料限制和付费者 | 访谈记录 + 基线 |
| 2. 历史项目回放 | 3 个 | 在不影响客户的前提下做人工/AI 对照 | 时间记录 + 双盲评分 |
| 3. 实时脱敏 brief | 1 个 | 验证工作流在期限和修改压力下是否成立 | 实际交付 + 修改记录 |
| 4. 付费行为测试 | 3-5 人 | 判断服务、项目包或订阅哪种更可接受 | 付款/订金/拒绝原因 |

总样本不大，不能估计市场规模，但足以排除明显错误方向，并决定是否值得继续开发。

## 3. 招募对象

### 主组：活动/品牌代理公司

- 客户经理、策划、项目负责人或创意负责人。
- 过去 6 个月至少做过 3 个客户方案。
- 愿意提供一个已结束、可脱敏的真实 brief 和最终交付物。
- 优先包含 2 名执行/策划、2 名客户/项目负责人、1 名负责人或老板。

### 对照组：B2B 企业市场

- 市场专员、活动营销、品牌或内容负责人。
- 过去一年至少负责 2 次展会、峰会、客户活动或整合营销项目。
- 能说明审批、品牌规范和销售协作过程。

### 不纳入

- 没有真实项目经历、只讨论想象需求的人。
- 只愿意看演示、不愿提供任何历史样本的人。
- 供应商、AI 从业者或朋友出于支持而给出的“礼貌性好评”，除非同时满足真实任务条件。

## 4. 招募话术

> 我在验证一个面向市场/活动团队的 AI 工作流，不是做聊天机器人。它尝试把不完整 brief、客户资料和公开证据，整理成可追溯、可逐段修改的方案初稿。我需要一个已经结束、可以脱敏的真实项目做对照测试。全程约 45 分钟，不需要你准备新材料。作为交换，我会给你一份基于原项目的新版结构和效率/质量对比。重点是找问题，不需要给好评。

对实时 brief 的邀请：

> 如果历史回放结果有价值，我希望再用一个当前但已脱敏的 brief 做小范围试用。所有外发内容由你确认，系统不会自动联系客户或修改任何平台数据。我们会记录实际耗时、修改量和错误，而不是只问主观感受。

## 5. 20 分钟问题访谈

访谈时不要先演示产品。先问最近一次真实项目，追问行为和材料。

1. 最近一次从收到 brief 到提交第一版方案，具体发生了什么？请按时间顺序说。
2. 最初拿到的资料有哪些，缺了什么，谁负责补齐？
3. 哪一步最耗时间？大概花了多少人工小时和自然日？
4. 第一版之后改了几轮？最近一次大改由什么触发？
5. 哪些信息最容易出错或无法核实？错了由谁承担后果？
6. 现在会用哪些 AI 工具？把 AI 结果放进正式方案前会怎么检查？
7. 哪些客户资料绝对不能上传到外部工具？谁有权批准？
8. 如果有工具能把这次项目的第一版时间减少三分之一，你愿意先给它哪一部分任务？哪一部分绝不给？
9. 这类工具由个人、部门负责人还是采购付费？过去买过什么替代方案？
10. 下一次类似项目大概在什么时候？是否愿意提供脱敏 brief 做测试？

必须记录：原话、角色、公司规模、任务频率、实际耗时、修改轮次、当前替代工具、数据限制、下次真实任务日期。不要把解释性总结写成原话。

## 6. 历史项目回放设计

### 三个项目类型

1. 一个品牌活动或整合营销方案。
2. 一个 B2B 展会、峰会或客户活动。
3. 一个只有会议纪要或口头需求、信息不完整的模糊任务。

### 输入材料

- 原始 brief/会议纪要。
- 当时可获得的品牌资料和公开链接。
- 最终交付物。
- 若可提供，修改记录、工时和结果数据。

最终交付物在生成阶段不得提供给 AI，只在评审阶段作为参考。

### A/B 条件

- **A 条件（基线）**：由原执行者说明当时人工流程、耗时和结果。若时间允许，可用相同材料重新做 45 分钟限时方案结构。
- **B 条件（工作台）**：使用相同输入，由同一人或同等经验者完成 brief 澄清、证据整理、方案骨架和审阅。
- **评审**：至少 2 名未参与生成的人匿名评分，隐藏 A/B 标签和工具信息。

这不是统计意义上的 A/B 测试，而是小样本配对回放。目的在于发现明显质量下降、时间浪费和高风险错误。

## 7. 记录时间

分别记录人工工时和自然周期，不能混成“效率”。

| 阶段 | 基线人工分钟 | 工作台人工分钟 | 基线自然周期 | 工作台自然周期 |
|---|---:|---:|---:|---:|
| 理解 brief/追问 |  |  |  |  |
| 收集与阅读资料 |  |  |  |  |
| 研究与证据整理 |  |  |  |  |
| 方案结构与初稿 |  |  |  |  |
| 人工核对与修改 |  |  |  |  |
| 格式与导出 |  |  |  |  |
| 合计 |  |  |  |  |

计算方式：

- 人工工时减少率 = `(基线人工分钟 - 工作台人工分钟) / 基线人工分钟`
- 周期缩短率 = `(基线自然周期 - 工作台自然周期) / 基线自然周期`
- 人工修改负担 = `工作台核对与修改分钟 / 工作台总人工分钟`

## 8. 双盲评分表

每项 1-5 分。1 分为不可用，3 分为达到普通第一版，5 分为可直接进入客户/内部评审。

| 维度 | 评分问题 | 权重 |
|---|---|---:|
| Brief 理解 | 是否正确理解目标、受众、限制和决策问题 | 15% |
| 证据质量 | 关键事实是否有来源，来源是否支持结论 | 20% |
| 策略逻辑 | 洞察、目标、策略、动作与指标是否连贯 | 20% |
| 创意适配 | 创意是否符合品牌和场景，而非通用套话 | 15% |
| 可执行性 | 节奏、资源、预算假设、责任和风险是否可执行 | 15% |
| 测量设计 | KPI 是否能被真实数据采集，是否避免伪 ROI | 10% |
| 表达与结构 | 是否易读、易改、易向客户或内部说明 | 5% |

评审者还必须标记：

- 严重事实错误数量。
- 品牌/语气错误数量。
- 法律、版权、隐私或承诺风险数量。
- 需要重写的章节比例。
- 愿意保留的章节比例。

## 9. 真实 brief 试用流程

1. 对资料脱敏：删除客户联系人、未公开价格、个人信息、合同和受限数据。
2. 记录开始时间和期望交付时间。
3. 系统先给出缺口清单，用户确认后再研究和生成。
4. 所有外部事实必须带 URL、标题、发布日期、采集时间和关键摘录。
5. 所有预算、效果和转化数字必须来自用户输入或标为假设。
6. 用户逐段接受、修改或驳回，记录原因。
7. 导出前执行事实、品牌、版权、隐私和数字检查。
8. 交付后 24-72 小时记录实际修改、内部/客户反馈和是否继续使用。

## 10. 测试阈值

以下数字是 **进入下一阶段的测试阈值**，不是已经取得的结果，也不是行业基准。

### Go：可以继续做可用 MVP

- 3 个历史项目和 1 个实时 brief 的人工工时中位数减少至少 30%。
- 第一版自然周期中位数缩短至少 50%。
- 可核实事实的来源覆盖率至少 90%。
- 最终外发版本严重事实、品牌、法律或隐私错误为 0。
- 盲评总分不低于基线，且至少 70% 的章节可直接保留或小改后保留。
- 至少 2/5 位目标用户主动要求在下一次任务中再用。
- 至少 1 位用户愿意为下一次真实任务付款或付订金。

### Continue with changes：继续服务式验证，不开发完整软件

- 人工工时减少 15%-30%，但用户认为证据/审阅价值明显。
- 质量不差，但操作步骤或资料整理负担过高。
- 有重复使用意愿，但没有付费行为。

### No-Go / Pivot：停止当前切入点

- 人工工时减少低于 15%，或核对与修改占工作台人工时间超过 50%。
- 来源覆盖率低于 80%，或同类严重错误重复出现。
- 盲评质量持续低于人工基线。
- 完成 1 个实时 brief 后，没有人愿意再次提供任务。
- 用户只对“做 PPT/写文案”感兴趣，而不在意证据、审阅和复盘；此时应考虑转为服务或培训，而不是继续做工作台。

## 11. 付费行为测试

先卖结果，不先卖软件。以下价格仅是测试锚点，不是定价结论。

### Offer A：真实 brief 加速包

- 输入：1 个脱敏 brief + 最多 10 份资料。
- 输出：缺口清单、证据卡、方案骨架、KPI 测量计划、一次修改。
- 测试价格：人民币 299 元/项目。

### Offer B：团队共创月

- 输入：最多 3 个项目。
- 输出：每个项目的证据化方案初稿、版本记录、一次复盘模板；另含一次 45 分钟 AI 工作流分享。
- 测试价格：人民币 699 元/月。

### 判定

- 口头接受价格但不付款：弱信号。
- 愿意付 20%-50% 订金并安排真实项目：强信号。
- 要求公司报销/开票：说明买方链条，需要继续核对采购门槛，不等于拒绝。
- 只愿意免费试用且不给真实材料：不计入需求。

## 13. 每周决策看板

只跟踪以下指标：

- 已完成有效问题访谈数。
- 已获得可脱敏历史项目数。
- 已完成配对回放数。
- 人工工时减少中位数。
- 第一版周期缩短中位数。
- 来源覆盖率。
- 严重错误数。
- 可保留章节比例。
- 重复使用请求数。
- 付费/订金数和拒绝原因。

不要使用页面访问、点赞、收藏、朋友好评作为核心验证指标。

## 14. 市场团队交付清单

市场团队拿到本包后应完成：

- [ ] 确认首批只招募活动/品牌代理公司，企业 B2B 市场作为对照组。
- [ ] 招募 5 位符合条件的从业者。
- [ ] 收集 3 个脱敏历史项目并签署资料使用确认。
- [ ] 建立统一计时和评分表。
- [ ] 指定 2 位独立评审者并隐藏 A/B 标签。
- [ ] 完成 1 个实时 brief，不自动外发任何内容。
- [ ] 对至少 3 人提出明确付费方案，而不是只问“愿意付多少钱”。
- [ ] 根据 Go/Continue/No-Go 阈值做书面决策。

## 15. 建议的 14 天安排

| 日期 | 动作 | 结果 |
|---|---|---|
| Day 1-2 | 确认招募名单、脱敏规则、计时表 | 5 人名单 + 资料规范 |
| Day 3-5 | 5 次问题访谈 | 基线与真实原话 |
| Day 6-9 | 3 个历史项目回放 | A/B 产出 + 时间记录 |
| Day 10 | 匿名评分 | 质量与错误对比 |
| Day 11-13 | 1 个实时 brief | 实际交付与修改记录 |
| Day 14 | 付费询价和决策会 | Go / Continue / No-Go |

若 14 天内没有合适的实时 brief，不要伪造测试。延长周期并明确标记“未完成”。
